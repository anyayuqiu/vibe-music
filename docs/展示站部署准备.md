# 音乐资料展示站部署准备

本项目仅展示歌曲资料和图片。服务器不提供音频上传、播放或下载。MinIO 用于封面与头像。

## 首次启动

1. 在空数据库导入 `sql/vibe_music.sql` 建表。当前脚本不含用户、管理员、曲库或音频地址；若迁移旧数据库，仍需清理其中的示例账号、音频地址和无使用权的封面。
2. 设置 `VIBE_INITIAL_ADMIN_USER` 和 `VIBE_INITIAL_ADMIN_PASSWORD`（至少 12 字符）。仅在管理员表为空时创建账号。创建成功后从运行环境移除这两个变量。
3. 在未纳入 Git 的 `application-dev.yml` 中设置 `vibe-music.jwt.secret`，至少 32 字符；更换该值会使旧登录令牌失效。缺少密钥时服务端会在启动时直接报错。
4. 设置 `VIBE_ALLOWED_ORIGIN` 为网站的 HTTPS 来源，如 `https://music.example.com`。多个来源用英文逗号分隔。本地默认允许客户端 `http://localhost:8090` 和管理端 `http://localhost:8089`。
5. 在服务器的外部配置目录创建 `application-prod.yml`，填写 MySQL、Redis、MinIO、邮件和百炼 API Key。用 `VIBE_PROFILE=prod` 和 `--spring.config.additional-location=file:/etc/vibe-music/` 启动 JAR；不要上传本机的 `application-dev.yml`。

AI 助手要求用户登录；每人两次请求间隔至少 12 秒、每日最多 30 次，全站最多同时处理 2 次。单次提问最多 500 字。会话最多 100 个，每个保留最近 12 条消息，闲置 30 分钟后在下一次请求时清理。

## 2 核 2 GB

在本地构建前端和 JAR，服务器只运行静态文件、Java、MySQL、Redis、MinIO 和反向代理。Java 建议先用 `-Xmx512m`，MySQL 配置小缓冲池，Redis 设置内存上限，并配置 swap。只对公网开放 80/443；MySQL、Redis、MinIO 控制台及 Java 端口留在本机网络。备份 MySQL 和 MinIO 数据。

生产前端的 `VITE_APP_BASE_API` 已设置为同源 `/api`；Nginx 需将 `/api/` 转发至本机 Java 的 `/`。MinIO 内部端点可用 `http://127.0.0.1:9000`，另设 `VIBE_MINIO_PUBLIC_URL=https://music.example.com/media`，让新图片返回公网 HTTPS 地址；Nginx 将 `/media/` 转发至本机 MinIO 的 `/`。数据库里已有的 `localhost:9000` 图片地址仍需迁移。上传图片限制为 JPG、PNG、WebP，最大 2 MB。
